# Rides: each drawing loads only when it's worn (Nov 1, 2026)

#442 (rides v2) drew rides from their source drawings, which put the 16 drawings in the main bundle: 770 → 825 KB gzip on every
player's first load, though only admins can wear a ride. Its decision note named this follow-up ("Repo footprint and download").

## What changed

- **Each ride's drawing is its own chunk** (`components/rides/load.ts`: one dynamic `import()` a ride; `loadRide`, `useRide`), loaded
  only when a ride is drawn: worn by you or someone in view in the town, or shown in the locker, a profile or on home. `kit.ts` is
  only the types now. Main `index` 2,588 → 2,413 KB, **824.6 → 771.9 KB gzip (−52.7 KB)**; the chunks are 1.2 to 6.5 KB gzip each
  (64 KB for all 16); the town's chunk 32.7 → 31.7 KB.
- **What every box needs is in the main bundle, measured ahead**: `town/ride-cells.ts` (generated by `scripts/measure-rides.ts`) now
  also holds each ride's tile box, every view's frames (time, where the pawn sits, the move's lift) and its trail's numbers, about
  3 KB gzip; a unit test checks them against each drawing and that only `load.ts` imports one, never statically.
- **Nothing moves while it loads**: home's pawn and ring, the profiles and the locker draw the pawn where it will sit (whole) and the
  ride appears under it (`data-drawn`); in the town the pawn walks on foot, as it already did while frames were composed, but in the
  rider's tap box and under its tag (`youSoon`, `ridersSoon` in render.ts), so neither moves when the ride appears.
- **Your own ride's chunk is asked for after the first paint** (main.tsx), and again when your look changes.

## Calls made

- **Before the drawing comes, the pawn sits in its seat's place, not on the ground** in home's, the profiles' and the locker's boxes:
  standing it on the box's foot would make it jump up onto the ride when it came. It's drawn whole (not cut at the seat) for that moment.
- **The registry keeps seats to a thousandth of a unit** (the test allows that), about 3 KB gzip instead of the drawings' 55.
- **The service worker still precaches every chunk** after install, as it does every other file (offline play); only the first load
  is lighter.

## Frame rate (eric.md's method)

Headless, `?crowd=50` by day, Canvas 2D, riding Riding Chirp, 5 s walking up and down, medians of four runs taken in turn against main
(bb5e7a18). Phone 390 × 844: main 47.5 fps (JS 3.22 ms, task 20.9), branch 44.8 (3.50, 22.0); the machine was busy (both ranged 43.6
to 50.3), so the phone was measured again: main 49.9 (2.97, 19.9), branch 48.5 (3.03, 20.3). Computer 1440 × 900: main 50.6 (3.31,
19.5), branch 53.1 (3.08, 18.6). Long tasks while walking: 1 on both (about 55 ms; one phone run each side had 0 or 2). Level with main:
the frame loop only adds a map lookup a person while a rider's frames are coming.
