# The ledger, part I (Nov 6, 2026)

Eric, Nov 6: "things like an audit trail for items does make sense … all these things are worth doing." (Audit of Nov 6, §1.)

- **The call:** an append-only `ledger` beside the balances (they stay the fast read and the truth), written only by `packages/server/src/ledger.ts`, in the same batch as each change. Each event is an op keyed as the audit says (`shop:…:<item>`, `ranked:<game>:<color>`, `drop:solo:<battle>`, `welcome:…:<n>`, `delete:<item>`); the same op twice applies once. Triggers refuse UPDATE and DELETE on it.
- **It names nobody:** each account gets a random ledger id (`ledger_accounts`), used where the audit's keys say `<user>`. A merge is a leg out of the guest and a leg into the account; a deletion closes every balance; both drop the id, so the rows stay without the player (the privacy page says so).
- **Also moved now:** boss crate buys (keyed by the new crate's row: two taps are still two buys) and admins' grants, so a crate's cost outlives its opening and tokens and keys reconcile. Squads' reward and free crate opens wait for part II (the guard test lists them).
