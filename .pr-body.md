## Music at 128 kbps

Eric, Nov 16: "128 is fine for the game." Light lane.

**What changed:** all 33 MP3s in `packages/app/public/music/` were re-encoded from 192 kbps to stereo CBR 128 kbps at 48 kHz, using ffmpeg libmp3lame. `themes.json` and `pad` are unchanged. The README, `docs/areas/bosses.md` and the new decision note `docs/decisions/2026-11-16-music-128k.md` were updated to match. The service worker's music hashes come from the file contents at build time, so players' cached 192 kbps copies are fetched again once.

**Sizes:** 67.5 MB → 45.0 MB in total (−33%). The five biggest files:
town-loop 4.31 → 2.87 MB; tiger-loop 3.99 → 2.66; dash-loop 3.87 → 2.58; chandy-loop 3.77 → 2.51; pig-loop 3.72 → 2.48.

**Loop check:** every file passed, including the intros and the town's solos.
- Each new file decodes to exactly the same number of samples as the old one.
- Each has the same encoder delay (1105 samples) in its gapless header.
- Cross-correlated against the old decode, each lines up at **offset 0**. This was measured over the first 20 s, and in 4096-sample windows at `pad` and `pad + loopSeconds`. For the intros the windows were at the start and at `introSeconds`; for the solos, at the start and at `seconds`.
- In those windows the waveforms match to within 15–26 dB SNR, which is ordinary MP3-to-MP3 difference.
- No changes to the encode or to `pad` were needed.
- The window at the very end of recluse-phase3-intro is digital silence in both files.

**The 192 kbps files:** tag `music-192k` on b3bd995 (main before this change). The tag push was refused (HTTP 403) from the helper's session, so it still needs to be pushed.

**Changed checks:** none. `music.test.ts` and `sw-versions.test.ts` pass (81/81).
