Two e2e flakes on main (run of dbc4ec7, both passed on retry), each fixed at its cause. Light lane: tests only, no app change.

**`e2e/chandy.spec.ts` (Dodge, both tests' phase checks).** The cause: the rAF sampler (`watch`) only records phases that a frame lands in. Dodge's slide is 600 ms at any pace (`dodgeSlideMs`, which `pace=quick` doesn't shorten), and one long frame on a busy CI runner skipped it. The spec treated frame samples as if every phase were sure to get a frame. The fix asks the e2e only for what a frame sampler can promise: the phases up to the first vote come in the timeline's order, and the long ones (scope, volley, vote) are each seen. The full order, slide and open included, is still checked by the unit test of the timeline (`packages/app/test/chandy-wired.test.ts`, "Dodge on screen").

**`e2e/alfil.spec.ts` (Slam right after a queen is taken).** The cause: the loop stopped at the first `MAMMOTH SLAM!` banner. Alfil's rage meter fills from material (rageSpeed 1.2, and the test's trades feed it), so a Slam from the meter could land before he took your queen, and the loop ended with took 0. No test switch holds the meter. The fix: the loop records the Slam count when the trigger goes in (on his first queen take) and stops only once a Slam lands after that. The banner checks count from that point.

Player-visible changes: none.

Changed checks, old → new:
- chandy (both Dodge tests): `s.dodge.slice(0, 5)` equals scope, slide, volley, open, vote → the phases up to the first vote are in the timeline's order, with scope, volley and vote each seen (`dodgeOpening`). The exact order stays in the unit test.
- alfil: the loop breaks on any Slam → breaks on the first Slam after the trigger. `MAMMOTH SLAM!` count `1` → `(Slams before the trigger) + 1`. The trigger now fires once, on his first queen take. Before, it fired again on every take, though the first one already set it.
- Unchanged: `took > 0`, `QUEEN DOWN!` = took, `QUEEN SLAIN!` = slew, no page errors.
