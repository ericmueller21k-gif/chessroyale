### Cause: (a), a test race. Not a drawing bug.
- Bo's copy of Ann's zzz is set as the server's answer to Bo's beat comes in (`here-net.ts` `beat` → `applyHere`, a fetch `.then`).
  `drawn` comes from `r.zzzList()`, the zzzs the **last frame** drew. Between the answer and Bo's next frame they disagree, and the test
  read them in two separate `evaluate`s.
- (b) is ruled out by the code. The town has no idle/dirty-frame skip: `Town.tsx` `frame` asks for the next `requestAnimationFrame`
  every time (it stops only for a hidden tab, a test hold, away or loading), and `render.ts` `draw` resets `nZzz` and draws the whole
  town every frame, so a zzz cleared by a beat with nothing else changing is gone on the very next frame.
- Evidence (local, CI's spec, desktop, Bo's page slowed 6x via CDP `Emulation.setCPUThrottlingRate`, a probe reading `them(bo, annId)`
  as the test does): in **5 runs of 5**, the read that first saw `zzz: false` still had `drawn: true`, and **the next read** had
  `drawn: false`. The window is one frame, every time.

### Fix
- The spec polls `[zzz, drawn]` together (`toEqual([false, false])`), as it already did for the zzz coming on (lines 70-73). Both
  places that read zzz, then drawn, are changed: old lines 66-67 (Bo sees Ann not away) and 82-83 (the failing one).
- A rule in `.claude/LESSONS.md` (Tests): a hook's "drawn" is the last frame's; poll it in one read with the state it follows.
