  level ring and LVL; the public profile's real "Level N" line; your profile's Level pill; the FAQ's "XP and levels"; the privacy
  policy's XP entry.

## What a player sees
- After a counted game: the box fills from the old XP to the new over 1.5 to 2.5 s, counting up, each part in turn ("12 min +120 ·
  Win +50"); a level-up fills to the end, pops "Level 8!", goes on from empty. Never a jump; nothing around it moves.
- No XP: the same box says why: "No XP: the game ended before move 10." / "you resigned before move 10." / "you left the match." /
  "Sign in to earn XP." / "No XP: test game." / "No XP: this account is banned."
- Home: "LVL 7" and the ring for everyone who can earn XP. Public profile: "Level 7" for everyone.
- Stills (deviceScaleFactor 2), branch `stills/xp-phase1`: a level-up mid-fill, a counted game done, "No XP: test game.", phone and
  computer.

## Review fixes (the independent review, `review/569`)
- **M1:** a solo result the server never timed (no `game`, or one already ended) earns no XP at all; a solo win also needs
  `XP.soloWinMinMinutes` (5) of the server's own time.
- **M2:** solo time XP is capped at `XP.soloMinutesPerDay` = 120 minutes an XP day (1,200 XP; the director's call, Eric may change it).
  Its leg's source is `solo` and its guard (the day's sum) is in the same statement, as the solo win cap. Past it, the box says
  "Daily solo limit +100" (a held-back win's +0 then left out: "… (Daily solo limit) … · Win (paid once today) +0" overflowed 320
  px), "Daily solo limit +0" beside a paid win, or "No XP: daily solo limit reached." (a new reason, `limit`).
- **m1:** `?xpgame` counts a game only where TEST_SWITCHES is "1"; an admin's on production makes a test game (lobby: `tested`; solo:
  `test_minutes = -1`, `SOLO_TESTED`).
- **m2:** the duel's box: "No XP: test game." for an unranked game, else the default "No XP for this game." when `xp` is missing.
- **m3:** the admins' boss-ultimate trigger marks its raid `tested`.
- **m4:** the friends' win cap is per opponent: a win today against a set sharing anyone blocks the next.
- **m5:** the opponents' ledger ids in one `IN (…)` query; the standing, ledger id and solo sum in one read; the two outcomes and the
  wallet after the batch in one read.
- **m6:** solo afk sends `left: true`; the server answers "left".
- **m7:** the box reads the waiting XP once; the fill starts no lower than it, so the bar never steps back; a grant whose fill has
  finished isn't played again in a later box (Squads' card, then its results).
- Nits: an old app's solo result stores `moves` NULL; `endSoloGame`'s comment says the order (taken off before the grant, never paid
  twice). Not done: the `before` race (display only, not trivial).
- Player-visible: the FAQ's "XP and levels" says the per-opponent cap, the solo win's 5 minutes and the solo daily limit.

- **Your name in the box (Eric, Nov 9: "it looks like the boss is the one leveling up"):** the top row reads "+37 XP · <your name> ·
  Level 2", the name centered, muted, one step smaller, ellipsized first when space runs short; the box keeps its size. Every screen
  with the box. Stills refreshed on `stills/xp-phase1`.
