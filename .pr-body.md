## Level-up reward card, and the inventory as a layer

Eric (Nov 22): the end screen's crate toast in the crate opening's blue look, centered, popping more, with OK and "Go to inventory"; on the mockup: "looks good", and "How do we make it so people don't have to like leave the town if they want to go to their inventory?" The answer, built here: the inventory opens as a layer over whatever you're on, so nothing underneath unmounts, and the button is never greyed. Decision: `docs/decisions/2026-11-22-inventory-layer.md`.

### What changed
- `components/RewardBox.tsx`: the approved mockup's card (centered, the crate screens' blue window, the pop of a crate's reveal, crate and key big). **OK** and **Go to inventory**. The mockup's greyed rule (`away`, "After your run" / "After the party") and `?mockAway` are removed. `Results.tsx` and `EndScreen.tsx` are back to main's.
- New `components/InventoryLayer.tsx`: the shop screen itself (`ShopScreen initial="crates"`, not a copy) shown full-window in a portal, inside the shop page's own frame (`fd-root framed fd-on-shop` → `fd-center`). Eric, Nov 22: "it should still look the same, like when you go to your inventory from the main menu". It is opaque, with no backdrop or card look. On a computer it uses the page's middle column, without the side menu and chat rail, whose links would leave the run or party. It pushes one history step, and Back, Escape or the phone's back gesture close it. App.tsx's popstate asks `inventoryTakesPop()` first. A capture-phase guard keeps keys from the screen under it. The card owns the layer, so when that screen moves on, the layer goes with it.
- The locker's delete dialog, the gambling warning and the shop's note now take their own Escape in the capture phase and stop it, so one Escape closes only the top thing.
- `e2e/areas.json`: InventoryLayer.tsx is mapped to the XP area, which now also runs quests.spec and tower-party.spec.
- Area pages: accounts, shop, crowd, ranked and squads.

### What players see
- After a game that pays crates or keys, a centered blue card pops in. It waits for you: OK closes it, and Go to inventory opens your Crates tab over the end screen. Back returns you to the same end screen, still in your tower run or party.

### Changed checks, old → new (none guards a rule in docs/rules/eric.md)
- xp-rewards, daily reward: "takes no taps" (`pointer-events: none`) and "goes on its own" (gone within 10 s) → Go to inventory is enabled, and OK closes the card.
- xp-rewards, level-up: `page.goto("/shop?crates")` → Go to inventory opens the layer on the Crates tab with the URL unchanged; the crate is opened inside the layer; Back returns to "Victory!" and the card doesn't come back.
- quests, finishing quests: the card is now closed with OK before Home is tapped (it was tapped through the toast before).
- tower-party, a party of two: **added**. A faked level-up on Ann's floor; Go to inventory opens the layer with the URL unchanged; the phone's back closes it; the party's end screen is still there (phase results), and "Back to the Battle Tower" carries on as before.

Risk to note: the card now takes taps over the end screen. Any other spec whose game pays crates or keys must tap OK first. None of the specs run here did; CI's run will show any others.
