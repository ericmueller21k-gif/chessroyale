## e2e lobby-chat: watch the full lobby from inside the page

Fixes main's retry-pass `[phone] e2e/lobby-chat.spec.ts:28` (three runs, three different steps after the bots fill). Test lane: e2e only, no game code.

**Cause (the test, not the game).** When the bots fill the queue, the server shows the full lobby for `FRONT_DOOR.fillShowMs` (1.8 s),
then starts the votes. The bots' hello lands 0.3 to 1.4 s after the fill (`QUICK_CHAT.botLobbyDelayMs` + `botLobbyGapMs`). After the fill
the test made about ten round trips (count "100", the hello visible, `phase === "lobby"`, then four `boundingBox` calls). On a slow runner
the last of them landed after the votes began, which explains all three failures (phase "vote"; the hello's queue gone; `boundingBox`
null). Reproduced on phone with CDP `Emulation.setCPUThrottlingRate` 4: **4 of 5 failed** at the fill.

**Fix.** An init script puts `queueBoxes()` and `watchFill()` on Ann's page. From before the fill, the page checks every frame and records the first frame
with all seats filled ("100") and a bot's hello showing: the phase then, and the queue's boxes. If the lobby moved on first, it records that
instead. The test asserts on that one frame. Nothing about the game's timing changed, and no timeout was widened. The boxes before and after the chat lines
are measured the same way (one evaluate, same rounding as before). Also: `--repeat-each` repeats shared one queue pool (3 or 4 players
in a queue); the pool name now carries `repeatEachIndex`. `CPU_THROTTLE=4` (env, not set in CI) slows both pages, to prove races like this.

**Is the game right?** Yes. Slowed 4x, all 5 runs saw every seat filled and a bot's hello before the votes began.

**Proof** (phone, `--repeat-each 5 --retries 0`):
| | before | after |
|---|---|---|
| plain | 3 / 5 (2 failed: the shared pool) | 5 / 5 |
| CPU slowed 4x | 1 / 5 (4 failed at the fill) | 5 / 5 |

Typecheck green. No unit tests touched. CI traces not read (the throttled run reproduced the failures directly).

**Checks changed (old → new):**
- `toHaveText("100")` + bot line `toBeVisible({ timeout: 3_000 })` + `phase === "lobby"` + `queueBoxes` after the fill → one in-page frame
  with all of them: `{ phase: "lobby", full: true, hello: true, boxes }`. Same checks on those boxes as before.
- `queueBoxes` (before/after the chat lines): Playwright `boundingBox` per piece → `getBoundingClientRect` in one evaluate (same numbers).
- None removed.

**Not in this PR (for the director):** `front-door.spec.ts:141-142` and `matchmaking.spec.ts:141` read the queue screen after the count
reaches 100, inside the same 1.8 s. Each is one quick look, so less exposed, but it's the same race.
