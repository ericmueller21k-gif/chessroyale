## A shiny ride's shine slid across the locker preview as a rectangle (Eric, Nov 15)

**Cause.** A painted region's clip id was `${p.id}-${name}`, the same namespace as every other id made from the paint's id.
`RideLayers` (Items.tsx) makes `${p.id}-seat` for the rider cut, the big rectangle that hides the pawn below the saddle. Boingo's
Pogo has a painted region named `seat`, so it got the same id. The rider cut is drawn first, so `url(#it5-seat)` found the rectangle
and not the seat, and the seat's shine slid across the whole preview. It happened wherever the pogo is drawn: the locker preview,
its Ride tile, the profile, the shop. The rodeo bull's region is also named `seat`, so it would have done the same. I checked
the other suspects on Eric's page: the same item drawn twice gets a new paint id per copy (no clash), the shine isn't in a hidden or
detached tree, and the blend mode isn't involved (the clip found was the wrong shape, not a dropped clip).

**Fix (the cause, not a checker).** Region clips get their own namespace: `regionClip(p, name)` = `${p.id}-clip-${name}`
(`components/item-paint.tsx`). No other id built from `p.id` (the paint's gradients `-g`/`-f`/`-s`, the rider cut `-seat`, a
drawing's own clips, masks and gradients like `-ice`, `-cane`, `-keepb`, `-bulbglow-b`) uses `-clip-`, so no region name can collide
again. Hollow's Bulb, the one drawing that pointed at a region's clip from outside (its glow inside the glass), now uses `regionClip`.
The shine itself is unchanged: same gradient, same roll, same blend.

Rides re-measured (`scripts/measure-rides.ts`, since item-paint.tsx is part of each ride's hash): only the 18 hashes changed, and
every measurement is the same.

profile). The pale rectangle sliding beside the pawn is gone.
