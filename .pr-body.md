## The street town never falls back to the old town

Eric saw the old Canvas 2D town on his iPhone (Nov 13, as admin). The street town's WebGL context lost twice in a minute, or not back in 5 s, reloaded the page at `/town?street=off`, which is the old town. iOS drops WebGL when the app goes to the background, so two app switches could do it.

**What changed**
- `?street=off` is gone. No e2e needed it.
- A context lost while the page is hidden doesn't count. It gets 5 s once the page shows again (`town/gl-fail.ts` `lossWatch`).
- A context that comes back is fine, however often. The "lost twice in a minute" rule is gone.
- A context not back, or WebGL failing to start (no WebGL 2, no context, or the shader fails): the street town reloads once at `/town` with the same query.
- If it fails again within 2 minutes of that reload, the town's box shows the loading card's look with "The town couldn't load on this device." and a **Reload** button, and nothing else (`afterFail`; the time is kept in session storage, and if there's no storage it shows the message, so it can't loop).
- Reporting: still once per page. A page that reloads reports its reason. The page that gives up reports the new reason `message` (`TOWN_GL_FALLBACK`). `lost-twice` stays in the list so the week's counts still read it. The `/admin/ops` and `ops:report` wording changed to match.
- The old Canvas 2D town's code stays: the street town is admin-only, so the old town is still every other player's town. Nothing to delete.

**Player-visible:** admins only (the street town). They never see the old town. At worst they see the couldn't-load message with Reload.

**Lane:** targeted. Specs: `e2e/town-street.spec.ts` (the town) and `e2e/problems.spec.ts` (the fallback report, the health view).
