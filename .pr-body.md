## Typecheck the e2e specs

**Why.** `npm run typecheck` ran `tsc` only over the six packages, so a spec's type errors only showed up in CI's e2e run, about 25 minutes later. On Nov 15 `box()` was taken out of `e2e/lobby-chat.spec.ts` while another test still called it (#724). This fixes the cause: `check` now typechecks `e2e/` too.

**What changed**
- New `e2e/tsconfig.json`. It extends `tsconfig.base.json` and adds the ES2023 + DOM libs (for `page.evaluate` bodies and `findLastIndex`), the `node` and `vite/client` types, and Preact JSX (specs import app modules that pull in `.tsx`). It covers `e2e/*.ts` and `playwright.config.ts`. The `e2e/*.mjs`/`*.js` scripts are left out. At run time Playwright reads only `paths`/`baseUrl`/`allowJs` from a tsconfig, so test runs don't change (`playwright test --list`: 1343 tests in 126 files, as before).
- The root `typecheck` script ends with `&& tsc -p e2e --noEmit`. `check.yml` calls `npm run typecheck`, so CI picks it up as is.
- New `e2e/perf-probe.d.ts` (types for the plain-JS `perf-probe.js` that `perf.spec.ts` imports), modeled on `ci-select.d.mts`.
- `e2e/areas.json`: `e2e/tsconfig.json` goes in `full`, like `tsconfig.base.json`. `e2e/perf-probe.d.ts` goes in `none`, next to `perf-probe.js`.
- `docs/areas/ops.md` has one line on this. Decision note: `docs/decisions/2026-11-15-e2e-typecheck.md`.

**Errors found: 89, now 0.** None were silenced: no `@ts-ignore` and no new `any`.
- **Config (12):** JSX not set, `import.meta.env`, `findLastIndex`, and the untyped `perf-probe.js` (its `unknown` results). Fixed by the tsconfig and the `.d.ts`.
- **Index reads under `noUncheckedIndexedAccess` (~45):** rects and points became tuples (`[number, number, number, number]` in boss-side and timber, `[number, number]` in squads-replay and squads-three-boards). Folio's marks got a `Marks` record over the dataset keys `Folio.tsx` always sets. A `!` was added where the spec has already checked the length (home-polish's hop log, home-layout, sound, resign, moo, town-controls, squads-replay's move, fairplay's SQL row).
- **Literal types too narrow (~15):** `town.spec`'s `const r = (w.__rot = {…})` took the object literal's `null`/`false` types, so it now assigns first and reads back. Other fixes: the `vibrate` stubs take `VibratePattern | Iterable<number>`, ranked-tiers types its `admin` default `(): boolean`, the piece-sounds `paths` array is `string[]`, and town-chat's `touch` takes the CDP touch type.
- **Missing fields in a spec's own type (5):** `town-fixed`'s `Cam` gets `snapped` (the hook returns it, `Town.tsx`). The `helpers.ts` fixture type gets `seenDefaultForTest` (it was declared in the object but not in the generic). `webkitBackdropFilter` is read through a typed `as`.
- **Narrowing (1):** in boss-smoke's `PLAYABLE` filter, `isPlayable` is a type guard, so the false branch narrowed `b` to `never`. The two checks are swapped; the result is the same.

**Real bug found (1):** in `tiger.spec.ts`, the flight check falls back to the pump's `boundingBox()` when the first frame has no pump box. It then read `from.w`, which doesn't exist on a bounding box (that has `width`), so `s` came out NaN and the release-point check would have failed whenever that fallback ran. It now maps `{ x, y, w: width }`.

**Time.** `npm run typecheck` went from 50 s to 62 s locally (+12 s for `tsc -p e2e`), and it is green.

**Checks changed:** none. Only types changed and the one tiger fallback was fixed; no assertion was added, removed or loosened. Lane: light (tooling and test types). The e2e run will be the whole suite because `package.json` and `e2e/helpers.ts` are shared foundations.
