## What changed
Eric, Nov 22: a reload mid-game left nothing in the match history, so "no one would ever resign"; only games past 10 moves are kept.
- **The mark:** at your 10th own move the app tells the server (`POST /api/xp/solo/real`: mode, players, team, boss, tier, checked as `/api/results` checks a result); sent again at each later turn until the server answers. Never for a Battle Tower floor, a test-switch or practice game. Under 10 moves nothing new is stored.
- **The loss:** a marked game whose result never comes is written by the server (`xp.ts abandonStatements`: last place, `abandoned` = 1, dated at the 10th move, no XP, boss token, quest or Welcome Crate count) at the first of: the next solo start (a second tab's, a tower floor's too: one open solo game per account), the app's load (`GET /api/me?settle=1`), any profile read 24 h after it began, or a guest joining an account.
- **Never twice:** every solo result keeps its game's id (`results.solo_game`); a late result for a game already recorded writes nothing. Races tested both ways.
- **Two tabs:** the load doesn't record a game another tab of the device played in the last 10 minutes (`brc.soloLive`); a mid-game read never does.
- **A game you finished is never recorded as left (review I1, I2):** its result is kept on the device *before* it's posted (`keepalive`), and dropped only on a 2xx or a 4xx other than 429; on no answer, any 5xx or a 429 it's sent again at the next start, load or sign-in. Reads and starts name its game (`unsent`), so none records it as left, stale or not. A new start waits for the last result's post.
- **A re-sent result earns no time XP (N2)**, so no win or daily reward either (the server's clock ran on); the game still counts.
- Settings: `SOLO_ABANDON = { minMoves: 10, staleHours: 24, liveMinutes: 10 }`. Schema: 6 nullable columns on `solo_games`, 1 on `results`; download and erase updated. `/api/me` stays at 5 round trips.
