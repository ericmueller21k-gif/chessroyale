## The installed iPhone app: a solid status bar, not a frosted one

**Eric's report (Nov 20):** in the Home Screen app, home's top bar (the HunChess wordmark and the chat, quests, shop, friends and settings buttons) looked blurry and washed out. In Safari's tab it was crisp.

### Cause as found
`index.html` asked for `apple-mobile-web-app-status-bar-style: black-translucent`, which draws the installed app's page *under* the status bar. Since iOS 26.1, iOS covers that band with its own frosted scrim, and a page can't turn it off ([WebKit 301994](https://bugs.webkit.org/show_bug.cgi?id=301994), still reported on iOS 27.2). Home's top bar already starts below `env(safe-area-inset-top)`, but it was still frosted: other projects report the same thing, with the frost reaching past the inset. None of our own layers caused it. The only `backdrop-filter`s are scrims and the chat box, and the tab (where the inset is 0) was fine. WebKit's own advice ([317153](https://bugs.webkit.org/show_bug.cgi?id=317153), June 2026): `black-translucent` "has been deprecated for multiple releases ... Please remove this key, and the status bar should automatically appear in the same color as the webpage."

### Fix
- `index.html`: the `apple-mobile-web-app-status-bar-style` tag is removed. iOS then draws a solid status bar and starts the page below it. The inset becomes 0 there, so every screen's `env(safe-area-inset-top)` padding collapses on its own and no screen needed changing.
- `theme-color` follows the theme. It's the front door's ground: `#14161b` dark, `#f4f2ee` light (`THEME_COLOR` in `theme.ts`). `index.html`'s script sets it before the first paint, and `applyTheme` keeps it in step. It used to be the dark `#1b1d22` in both themes. The manifest's `theme_color` is the dark one too.
- Decision: `docs/decisions/2026-11-20-ios-standalone-top.md`. Area page: `docs/areas/ops.md`.

### Player-visible changes
- Installed iPhone app: a solid status bar in the page's color, light or dark, with the app below it. No frost.
- Safari's tab: nothing moves (its inset was already 0). Where a browser tints its bar with `theme-color`, light mode now gets a light bar instead of a dark one.
