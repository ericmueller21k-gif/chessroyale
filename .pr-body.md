## Payments PR 5: purchases storage

Row 5 of the payments design's build (`docs/decisions/2026-11-17-payments-design.md`, section 2): the tables, ledger kind `purchase`,
earned-first spending, refundable, delete and download. **No UI, nothing sold:** nothing calls the checkout or the credit yet but
tests (Stripe is PR 8). Lane: **full** (money, stored data); the `full-e2e` label and the independent review are the director's.

### What changed

- **Tables and columns** (`packages/server/src/purchases.ts`, `PURCHASES_SCHEMA` / `PURCHASES_COLUMNS`, wired into accounts.ts's
  runtime schema): `purchases` (session_id PK, user_id, pack, coins, remaining `0..coins` CHECK, cents, tax_cents, payment_intent,
  card_country, status, refunded_cents, created_at, paid_at) and `refunds` (op_id PK, session_id, user_id, kind, cents, coins,
  stripe_ref, status, comment, created_at), with indexes; `users` + buy_band, buy_band_at, refund_count, hold_until, chargebacks,
  closed_at, closed_reason, held_taps.
- **`PAYMENTS`** in settings.ts: the five packs ($1.99/200 … $49.99/6,000), `currency` "usd", `refundDays` 14, `commentMax` 500.
- **Core rules** (`packages/core/src/payments.ts`): `spendPlan` (earned first, then the oldest purchase's), `refundableCoins` (14 days,
  never more than the coins), `packOf`, `boughtOf`, `inRefundWindow`.
- **Ledger kind `purchase`** (ledger.ts): each purchase's `remaining` is a balance (asset id = the session id) beside the wallet's coins.
  `leg.purchase`, `spendLegs`; `HOLDINGS` covers it, so the daily check, the backfill, a guest's merge and deleting cover bought coins.
  **`leg.coins` now throws for a negative amount:** every spend goes through `applySpend`, so none can skip earned-first.
- **`creditPurchase(session)`**: one op `pay:<session>` (reason `purchase`): coins +N and purchase +N, the row marked paid, in one
  batch; a second call (or three at once) pays nothing. Pays nothing for an unknown session, unpaid, wrong price/currency/buyer, a
  guest, an account gone, a row not pending. **`recordCheckout`**: the pending row (PR 8 calls it), never a guest's.
- **Earned first** (`applySpend`, used by the coin shop's `buyItem`): earned, then the oldest purchase's `remaining`, in the spend's own
  op, each draw guarded at its read value and earned at its read value; a race is planned again once, then "That didn't go through.
  Try again." (nothing charged). A refusal with the coins unchanged (the item's yours already) isn't retried.
- **Refundable** (`refundable`): the total and the purchases in the window.
- **Delete and download** (account-data.ts store `purchases`): the download has every purchase and refund (and the users columns in
  `account`); deleting keeps the rows as `deleted`'s (sales records), unspent coins closed in the ledger, the refund comment erased.
  `TODO(payments PR 9)` at `deleteAccount`: offer the refundable amount back first.

### The migration

The runtime schema, as every table (accounts.md, "The database"): two `CREATE TABLE IF NOT EXISTS` (+ 4 indexes) and eight
`ALTER TABLE users ADD COLUMN` (the three counts `INTEGER NOT NULL DEFAULT 0`, the rest NULL), so every existing account reads "never
asked, none, not held, open". Forward-only; nothing existing is rewritten. Tested on **a copy of today's schema** (made by
`ensureSchema` on main at 92320601: `packages/server/test/fixtures/schema-2026-11-26.json`) with live-like rows: every row unchanged,
the defaults filled, the same shape as a fresh database, the ledger check still empty, a second run a no-op, and a purchase and spend
working after it.
