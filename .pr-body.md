## e2e: Chandy's Dodge vote flake fixed at its cause; the town deploy flake now reports its stage (not fixed)

**`e2e/chandy.spec.ts` (Dodge, round 3's tap), fixed.** The vote buttons never move: sampled every frame through whole votes, the box stayed the same and the element was never replaced. Playwright reports "not stable" when the button is removed mid-check, which happens when the vote closes. The cause is the test's timing. It waited a fixed `lastTeleport + 150` ms after `toBeVisible`, and that check retries every 100/250/500/1000 ms, so it can see the vote up to 1 s late. Measured under load, the vote closed 2.2 to 2.8 s after the test saw it, which left round 3's tap 0.2 to 0.85 s. Fix: `afterTeleports(page, k)` waits on the vote's own countdown in the HUD. This is a test-only problem; a player's tap isn't affected.

**`e2e/town.spec.ts:221` (old tab after a deploy), not fixed.** I couldn't reproduce it here: 12/12 alone, 16/16 at 8 workers with CPU burners, and the whole town spec under load. From the CI trace (run 44467157290): the next version's cache existed in every poll, so the next worker's install began. `next` stayed false for 60 s. That fits three stages: install threw (redundant), stuck activating, or waiting for the old worker's in-flight work. I couldn't tell them apart. The change: `register` is now awaited, the next worker's states are kept as they change, and a failed poll throws with them, for example `the next worker's states ["installing","installed","activating"]; now installing none, waiting none, active /api/e2e/sw.js:activating, in charge …`. I checked this by forcing a 1 ms timeout. The next CI failure will name the stage.

Proof (locally, `--retries=0`):
- Chandy Dodge test, after the fix: 10/10 at 4 workers plus 2 CPU burners. Before the fix: 10/10 at that load and 10/10 at 4 workers, so it didn't reproduce on demand. The timing above is the evidence.
- Town 221 with the report: 6/6 at 3 workers.

Changed checks (old → new):
- chandy.spec "Dodge: …": `waitForTimeout(teleport + 150)` ×3 → `afterTeleports(page, k)` (the HUD's countdown ≤ (vote − last teleport − 150) ms). The assertions are unchanged.
- town.spec 221: `void register(...)` → awaited; the poll's failure message now adds the worker's stages. The assertions are unchanged.
