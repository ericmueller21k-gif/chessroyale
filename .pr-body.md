Solo games: one left after 10 of your moves counts as a loss (step 1 of 2)
## What changed
Eric, Nov 22: a reload mid-game left nothing in the match history, so "no one would ever resign"; only games past 10 moves are kept.
- **The mark:** at your 10th own move (core's `ownMoves`, as XP counts them) the app tells the server once (`POST /api/xp/solo/real`, the mode, players, team, boss and tier, checked as `/api/results` checks a result). Never for a Battle Tower floor or a game with a test switch or practice on. Under 10 moves nothing new is stored.
- **The loss:** a marked game whose result never comes is written by the server (`xp.ts abandonStatements`: last place, `abandoned` = 1, dated at the 10th move, no XP, boss token, quest or Welcome Crate count) at the first of: the next solo start (same transaction as the start), the app's load (`GET /api/me?settle=1`), or any profile read 24 h after it began. Its row goes in the same transaction.
- **Never twice:** every solo result keeps its game's id (`results.solo_game`); a late result for a game already recorded (as left, or posted twice) writes nothing. Races (a result vs a start or a load) were tested both ways.
- **Two tabs:** the load doesn't record a game another tab of the device played in the last 10 minutes (`brc.soloLive`, `SOLO_ABANDON.liveMinutes`); a mid-game profile read never records it.
- **A game you finished is never recorded as left:** a new start waits for the last result's post ("Again" can be quicker), and a result that couldn't be sent (offline) is kept and sent before the next start or at the next load.
- Settings: `SOLO_ABANDON = { minMoves: 10, staleHours: 24, liveMinutes: 10 }`. Schema: 6 new columns on `solo_games`, 1 on `results` (the usual ALTER list); download and erase updated. `/api/me` stays at 5 round trips (a read first, so a profile read with nothing to record writes nothing).
- Step 2 (Resume / Forfeit) can call `abandonSoloGame(sql, user, { game })` for Forfeit and skip the load's `settle` for a game the device can resume.
