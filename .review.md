# Review: PR #791, Big Boy (b): fair play and the Last Stand with his toys

Reviewer: a fresh read-only helper (fair play and the Last Stand, effort xhigh). Branch `claude/bigboy-powerturn` at
`f057a57`, diffed against `origin/main`.

**Verdict:** the rules code is right. `toysTakeMove`, `toysTakeReply` and `toysAfterCrowd` agree with what the match
actually allows, solo and online, and no other boss's behavior changes. I found one medium issue, which is online trust:
the judge's reply now decides the Last Stand, and nothing checks the reply. I also found one low test gap and one nit.

## Findings

### 1. Medium: online, the boss's reply now decides Big Boy's Last Stand, and no one checks that reply

- **Where:** `packages/chess/src/bosses/bigboy.ts:258-273` (`toysTakeReply`) and `packages/chess/src/runner.ts:1075-1080`
  read `evaluation.replies[played]`. Online that value comes from a device:
  - `packages/server/src/lobby.ts:3414` passes `s.replies` from the judged board.
  - `packages/chess/src/judge.ts:201` (`baseBoard`) copies each `reply` from the device's report without checking it.
    `okScore` checks only `move` and `expected`.
  - `packages/chess/src/judge.ts:226` (`boardsAgree`) compares best move, scores and bot picks, but not `replies`.
  - `packages/server/src/lobby.ts:3852` keeps judge `a`'s board, including its replies, whenever the two judges agree.
- **What changed:** before this PR, the reply only decided what the save *showed* (`legalReply ? { reply }`) for
  every boss. Now, for Big Boy with toys up, it decides whether the Last Stand comes at all. The agreed numbers can't do
  that on their own.
- **Failing scenario:** Big Boy, a 3-tall tower on d7, and the crowd hangs its queen with `d1d5`. Both judges agree on
  the scores (the loss passes the bar). The honest reply is `d8d5`, which the tower blocks, so the save should sit out.
  - The first judge's modified client reports `reply: "g8h7"` (any legal reply the toys leave open). `toysTakeReply`
    returns false, and the Last Stand fires: the move is taken back and every crowd player gets power-ups.
  - The reverse also works: reporting a blocked reply where the real one is open suppresses a save that was due.
  - The PR's own match tests show that the reply alone flips the outcome: `round(tower("h3"))` with the reply against
    `round(tower("h3"), BLUNDER, null)`.
  - The judge doing this is usually a crowd player's device, and the crowd profits from the save.
- **Scope:** this needs a modified client in a judge seat (or a lone host). The save comes once per game. The host-alone
  path is already `unvouched`. Not a false-flag risk for honest players.
- **Suggested fix (least code):** when two judges agree, keep only the replies they both name identically. In
  `settleTask`/`accept` for `"agreed"` (and `"majority"`), set `board.replies` to the entries where
  `t.boards[a].replies[m] === t.boards[b].replies[m]`. A missing or disputed reply then reads as unknown, and the save
  sits out, which is the rule the decision note already uses.
  - The engines are deterministic at tolerance 0, so honest judges' replies match and nothing changes for them.
  - Optionally, also drop in `baseBoard` any reply that isn't a legal move after its move.
  - Alternative: add `replies` for the scored picks to `boardsAgree`. That makes a mismatch a dispute, which goes to the
    engine server, so it costs more.
  - Whichever is chosen, note it in the decision file. It touches the judges' protocol handling, which is full lane.

### 2. Low: the tests don't cover his open-tower turns in the Last Stand, and the AUDIT row for Big Boy no longer tests his real rule

- **Where:** `packages/chess/test/bigboy.test.ts:905-917` and `packages/chess/test/king-save-altered.test.ts:132-136`.
- **Gap 1:** the `toysTakeReply` cases use towers his reply slides *through* (d7, d6) or that are off its path (b3, h3).
  None has a reply that lands *on* the tower, where `hisToppleOpen` decides. If `toysTakeReply` passed `false` instead
  of `hisToppleOpen(next, s)`, every test would still pass. The Last Stand would then sit out wrongly on his rare open
  turns whenever the feared reply is the topple.
- **Gap 2:** the Big Boy row of the `AUDIT` table now passes only through the "reply unknown" path (its scripted judge
  names no reply, as the PR's comment says). It would pass even if `toysTakeReply` were broken everywhere else.
  `bigboy.test.ts` does cover the real rule, so this is a note rather than a hole.
- **I checked the behavior itself (throwaway probe, not committed):** 24 Big Boy battles (12 seeds, both sides, half
  with `?power=tower`, `towerBossChance` 0.5). For the played move, every legal reply `x` gave
  `toysTakeReply(p, fen, played, x) === (bossAllowed after the move bars x)`. That was 22,112 checks over 82 crowd
  topples, 78 turns with his moves barred and 10 turns with the tower open to him and a reply onto it, with no mismatch.
  `powerTurn(boss, fen) === (crowdAllowed !== null)` held on every turn. So the code is right today; only the guard is
  missing.
- **Suggested fix:** add one case with a 2+ tall tower on his reply's destination square, at a `seed`/`turn` where
  `hisToppleOpen` is true and one where it's false. Pick the seeds by trying `powerRoll(seed, "his-topple", turn)`.
  Expect `false` and `true`.

### 3. Nit: an empty scatter still counts as "toys up" when the reply isn't known

- **Where:** `packages/chess/src/bosses/bigboy.ts:259-260`.
- **What:** `scatter.squares` can be `[]`: a topple with no empty square nearby, or its only block stepped on with the
  limit lifted. With the reply unknown, `toysTakeReply` returns true and the save sits out, though no block stands. This
  is the same as before the PR and very rare.
- **Fix:** guard with `toyBlockSquares(p).length === 0`, as `toysTakeMove` effectively does.

## Checked and found right

- **Fair play (`toysTakeMove`):** it uses the same `toyStops(m, p, fen, true)` as the crowd's `crowdFilter`, and lifts
  the same way when every move is stopped. So it equals `crowdAllowed(...) !== null` without the God King's barred move.
  - Castling (the way runs on to the rook's corner), double steps, promotions (all four), knights jumping and en passant
    all go through `moveSquares`, unchanged.
  - The runner passes `board.fen` (crowd to move, before the move) and the boss state before `afterCrowdMove`
    (`runner.ts:926`).
  - The server records the runner's `power` flag (`lobby.ts:4354`). The new server test compares it with the round's
    `allowed` list, and would fail if `fen` were dropped.
- **The Last Stand model (`toysTakeReply` / `toysAfterCrowd`):**
  - `toysAfterCrowd` is a straight extraction of the old `afterCrowdMove` body: same order, same `BOSS_POWERS`, no
    mutation of the live state.
  - An expiring scatter (`until <= p.turn`) is gone for his reply. A boss-topple scatter (`until = turn`) blocks the
    crowd's turn but not his reply. A crowd topple scatters with `until = turn + 1` and blocks his reply.
  - `p.turn` at the Last Stand check equals `p.turn` at his reply (`preparePowers` runs only with the crowd to move), so
    `hisToppleOpen` is the same draw.
  - His limit lifting when every move is stopped matches `bossAllowed`.
  - The judge's reply format matches `legalMoves` (UCI, `pv[2]`; Chess960 is off for his standard start).
  - The Big Bounce at the start of his turn isn't modeled. That is per the Oct 24 decision ("powers still to come don't
    count").
- **Other bosses:** none defines `standAltered`. Every other `powerTurn` takes `(boss)` only, so the extra `fen` is
  ignored. `boardAltered` without `stand` is the general rule as before (for Big Boy it is still true while toys stand,
  through `bossStops`). There are no wrappers or forwarders of `powerTurn`. Production callers are only
  `runner.ts:926/1080`.
- **The loss the save measures** is against the best *allowed* move (`withoutBarred` filters by `crowdAllowed`, toys
  included). That supports the note's call to look only at the reply.
- **Commands run:** `npm run typecheck` and the vitest runs of `bigboy.test.ts` plus `king-save-altered.test.ts`
  (72 tests) and the server's "Big Boy online" tests (8) all pass.
