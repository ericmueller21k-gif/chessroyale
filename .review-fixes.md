# PR #839 (Battle Tower: two lives): the review's fixes and the e2e failure

Each finding was checked against the code before changing it; all six held.

## Findings

1. **Fixed (important).** `preparePartyFloor` (server `tower.ts`): each copy's floors lost are counted below **its own** party floor
   (`partyFloorOf`), not the plan's. A life spent in the party's room now stays spent when the plan goes back below it (one member's free
   leave), and floors lost alone (always at or above the copy's party floor) still come back with the floors played alone, as the
   decision says. Tests added in `packages/server/test/tower-party.test.ts`: the reviewer's scenario (Ann free, Bo loses, re-form in
   both seat orders keeps Bo's life spent; the replay won: on to 3 with one life, party best 2), the three-member variant (one free,
   one counted leave, one win), and a copy that spent a life alone getting it back on re-forming. The first two fail on the old rule
   (checked by reverting the line).
   - A side effect, handled: the party can now replay a floor already on its `lost` list and lose it again, so `lostWords` collapses
     repeats ("Lost floor 2 twice", "Lost floors 2 twice and 5"). Not changed (cosmetic, rare): a floor lost and then won on the replay
     is still left out of the run view's `beaten` bosses (the list holds floors, not attempts). Noted in the decision.
2. **Fixed.** `settleKept`'s finish-409-with-run branch takes the outcome as "lost" when the device sent "won" and the run's `lost` holds
   the floor; `TowerResult` now uses the server's `end.outcome` once it has answered. Unit test added. Not changed: the cosmetic recap
   gap when the run ended elsewhere (`run: null`, no `lost` in the 409), as the review allowed.
3. **Fixed.** A stop answered "between" with the run still on the kept floor is free (`free` set), so Town goes to the lobby. Unit test
   added (free on the same floor; not free when the floor moved on).
4. **Fixed.** Core `finishFloor`: only a floor not won can end a run (`outcome !== "won" && lost.length > s.lives`). Core test added
   (lives lowered to 1 with two lost: a win climbs on, the next loss is out).
5. **Fixed.** `TOWER_WORDS.climb` and the new `TOWER_WORDS.livesAClimb` are built from `BATTLE_TOWER.lives` (`livesWords`, `ordinal`);
   TowerDesk uses the latter. Unit test added.
6. **Fixed.** `TowerResult`: a leave the server made free reads "You left floor 8. It waits for you.", its sub line the same floor next,
   `data-tower-result="free"`.

## The CI failure (`e2e/tower-party.spec.ts:172`, phone and desktop)

Not the words. Measured in the real card: on this branch **every** three-line text overflowed the plan box by 2 px, including lines this
PR never touched (the ban line, the deleted-account line); on main's build all of them fit, the lives worst case too. The plan line's
font comes from two equal-specificity rules, `.tw-plan` (tower.css, 12 px / 1.3) and `.town-card-text` (town.css, 13 px / 1.35), so
the winner was whichever stylesheet loaded last. On main tower.css rode only with the match screens' chunk and usually loaded after
town.css; this PR's `TowerHearts` import in `Town.tsx` puts tower.css in the town's own preload list, before town.css, every time. The
box (3 × 1.3 em) then held 13 px text at 1.35: 2 px short. Fixed at the cause: `.tw-desk .tw-plan` and `.tw-desk .tw-desk-note` win by
selector (the card looks as on main). The other elements carrying both a town and a tower class are already order-proof
(`.town-btn.tw-over`) or have no tower rule (`tw-solo-go`). Words unchanged: with the fix the current worst case, lives included, fits.
